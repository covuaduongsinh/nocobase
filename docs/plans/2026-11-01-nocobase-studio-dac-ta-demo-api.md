## 2. Mô hình quyền thực tế (`/api/access/*`)

- Ba vai trò built‑in: **owner** (không sửa được), **admin**, **contributor** (vai trò mặc định cho thành viên mới: `access/settings.defaultRole = "contributor"`); có thể tạo vai trò tuỳ biến (`POST /api/access/roles`), gán nhiều vai trò cho một người (`PATCH /api/access/members/{userId}`).
- Một vai trò gồm 3 phần: **pages** (enum 11 trang: `pm-my-issues, pm-issues, pm-projects, agents, runtimes, skills, usage, rel-apps, reports, project-memory, knowledge`), **settings** (bật/tắt: `pm.general/read|update`, `pm.labels/*`, `pm.members/invite`, `agents.agents/read|manage`, `agents.runners/*`, `agents.prices/*`, `rel.environments/*`, `kb.indexing/read|configure|rebuild`, `studio.apiKeys/read|manage`, `studio.personalApiKeys/create`, `studio.git/read|manage`, `studio.roles/read|manage`, `user/read|update|disable|enable|reset-password|assign-role`), **abilities** (business action ở mức `none | related | all`: `pm.projects/view|create|manage|delete`, `pm.issues/view|create|edit|comment|moderate-comments|close|change-owner|delete`, `pm.attachments/upload`, `agents.agents/edit`, `rel.apps/view|read-logs|create|configure|upload|deploy|deploy-protected|operate|delete`, `kb.knowledge/read|edit|manage`).
- `GET /api/access/catalog` trả **catalog** mà các plugin đăng ký (businesses + settings + sections có i18n key), nên trang Roles được sinh tự động từ catalog, không hard-code.
- Contributor: xem/sửa issue "related", tạo project, không xoá, không deploy protected, KB related.
- Agent thực thi được cấp business actions giới hạn (từ demo): `pm.projects/view|create|manage`, `pm.issues/view|create|edit|comment|close|change-owner|delete`, `pm.attachments/upload`, `rel.apps/view|read-logs|deploy`, `kb.knowledge/read|offer`, `studio.git/open-pr`, `studio.previews/manage`, `studio.reports/read`.

## 3. Lead agent (project manager) — cấu hình thực tế

`GET/PATCH /api/projectManager` (`StudioProjectManager`): `name` ("Lead Agent"), `description`, `firstChoiceAgentId`, `fallbackAgentId`, `fallbackAfterSeconds` (120), `delegationQueueTimeoutSeconds` (600), `commentRunLimit` (20), `principles` (null = dùng `builtInPrinciples`), `choices` (agent khả dụng). Trong projects, nó là executor kind `agent`, id `studio-project-manager`, `isDefault: true` (issue mới không chọn executor sẽ về Lead Agent). Lead agent chạy bằng tool+model của agent "first choice" (nghĩa là nó **cũng là một run trên runner**, không phải dịch vụ riêng).

**Nguyên tắc điều phối built‑in** (tóm tắt): chọn agent theo mô tả "Good at" (design/khó → agent lý luận mạnh; triển khai thường/lớn; việc nhỏ; viết yêu cầu; review → không yếu hơn tác giả, ưu tiên khác nhà cung cấp, không bao giờ là model viết code; đọc CI fail); chỉ dùng agent `canStartNow`, nói rõ khi bỏ qua agent tốt hơn; không có agent → `blocked` + `needsYou`; fail 2 lần cùng bước → đổi agent, fail tiếp → blocked. Hỏi "approach" ngắn trước khi code khi thay đổi chạm nhiều package, dữ liệu/migration, concurrency, quyền, hoặc issue không nói cách làm. **Chỉ một bước đổi code tại một thời điểm**; review/điều tra chạy song song ở chế độ read‑only. Chỉ chuyển bước khi run đã kết thúc (Studio gửi input "step-ended"). Không reassign trước khi hết queue timeout; sau khi Studio xác nhận rút run mới chọn agent khác. Sẵn sàng nghiệm thu khi PR qua review + checks pass → `in_review` + `needsYou` + delivery report đầy đủ (`--acceptance-file`). Review yêu cầu sửa → trả lại tác giả, rồi review lại. Run fail không có reply → Studio tự trả lời thay; `runnerDiskFull` và `toolQuota` không tính là thất bại, chuyển ngay sang runner/agent khác (ưu tiên khác nhà cung cấp). Check fail → đọc log, phân biệt flaky/do thay đổi, nhờ người rerun hoặc giao sửa. Mọi quyết định cần người → `blocked` + `needsYou` cụ thể.

**Chỉ dẫn mặc định cho agent thực thi** (`agents.instructions`, tóm tắt): chỉ làm bước được giao trong comment mention; **đúng một comment trả lời mỗi bước** (trong thread của hand‑over, nêu việc làm, kết quả, link nhánh/PR/preview, việc còn lại, theo skill comment‑style; không đăng tiến độ giữa chừng vì mỗi comment đánh thức project manager; không mention ai); thư mục làm việc cố định dùng chung giữa các run của một task trên một runner → phối hợp trước khi sửa; **tự commit/push** (runner không bao giờ commit/push hộ), `git push origin HEAD:refs/heads/<branch>`, không rewrite history đã push, theo AGENTS.md, PR/commit tiếng Anh, changeset nếu repo dùng, điền đủ PR template bằng `--body-file`; Studio tự link PR trên nhánh issue, `nb-studio pr link/unlink` cho PR khác; khi bàn giao kèm tiêu chí nghiệm thu + ảnh (`nb-studio issue comment add <issue> --reply-to <comment> --content-file reply.md --attach x.png`); khi review: đọc diff + issue độc lập, nêu vấn đề có file/dòng, kiểm tra PR template, nói rõ merge được không, kiểm tra thay đổi `.nb-studio/memory/` theo skill `studio-memory`; `Mode: read-only` = không đổi file/commit/push; không đổi trạng thái issue, không giao việc; thiếu thông tin → hỏi một câu trong thread rồi kết thúc lượt; hành động trong quyền người giao việc; viết comment theo ngôn ngữ của issue.

## 5. Vòng đời issue theo dữ liệu thật (PM‑3586 "Bulk import customers")

1. Owner tạo issue (comment đầu do người: "Please take care of …; bring me a delivery I can check against this criterion: …").
2. Lead Agent (run) comment hand‑over #1: "Next: establish the smallest workable approach… `[@claude · claude-opus-5-5](mention://agent/<id>)` inspect … **Mode: read-only** … I chose you for design".
3. Claude trả lời trong thread (approach ngắn, "No files were changed").
4. Lead Agent hand‑over #2: "Next: implement the agreed scope, then hand the result to an independent reviewer. `[@codex …]` take … through implementation".
5. Codex trả lời: "Completed … Focused tests passed; the change is ready for review" + PR `feature/customer-import` (#12).
6. Lead Agent hand‑over #3: "Next: independently review the proposed change. `[@claude …]` read the requirement and the diff…" (trigger `mention`).
7. Claude: "Review approved. Focused verification passed; no blocking findings."
8. Lead Agent: `in_review`, `needsYou` = "Import the sample file in preview and reply "accept" if the messages are clear.", `acceptance` = Delivery report (## Result / ### Evidence (test + link PR) / ### Acceptance decision / ### Acceptance criteria / Delivery images).
9. Owner: Merge trong Studio (`POST git/pullRequests/{id}/merge`, `mergeability: clean`, `ciState: success`, checks `studio-crm-preview / build`) → `done` tự động; hoặc Send back (`POST issues/{id}/sendBack`).

Trạng thái phụ Studio tính toán (`StudioIssueProgress.state`): `working | queued | checksPending | needsDecision | waitingForContinuation | inReview | notStarted | finished | idle`; kèm `agent`, `step` (dòng đầu hand‑over), `since`, `runner`, `pullRequest`, `needsYou`, `next`, `explanationCommentId`, `handOver`, `personalRunnerRequests`, `managerWait`. Agent queue (`agentBoard`) mỗi dòng `state: waiting | working | queued | idle` + lý do chờ (`waiting.kind` vd `review`, `waitingFor` người). Run (`issueRuns`): `status: queued | dispatched | running | completed | failed | cancelled`, `trigger` (vd `mention`), `attempt`, `summary`, `failureReason`; transcript qua `issueRuns/{runId}/events`.

## 10. Hệ quả cho Dương Sinh Studio

1. **Lớp Studio = 186 route + bảng dữ liệu tương ứng** (xem phụ lục A, thẻ Studio) — đây là danh sách việc chính xác để tự viết; phần còn lại (467 route) có sẵn trong plugin mở.
2. **Lead agent là một agent chạy trên runner** với prompt nguyên tắc + CLI; không cần dịch vụ điều phối riêng. Dương Sinh Studio sẽ viết `ds-project-manager` với nguyên tắc tiếng Việt tương đương (mục 3) và 5 skill `ds-*` theo cấu trúc mục 4.
3. **Vai trò**: dùng mô hình owner/admin/contributor + default role + catalog tự sinh (mục 2), không tự nghĩ ma trận mới.
4. **Git**: bắt đầu bằng connection `kind: token` (PAT) + polling 60 s, nâng lên GitHub App + webhook sau; GitLab/Gitee không cần.
5. **CI**: tái tạo file workflow chuẩn (mục 6) với CLI `ds-studio` và API key tổ chức; với repo NocoBase 2 thay bước `pnpm build --tar` bằng `node setup/verify.mjs` trên dịch vụ NocoBase 2 trong job và báo `check report`.
6. **Manifest CLI** là tính năng nền tảng của `app-cli-client` → chỉ cần `describeRoute()` đúng cho mọi route là CLI `ds-studio` tự có lệnh.
